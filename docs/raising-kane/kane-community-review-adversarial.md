# Adversarial decision: FixList, with HandoffLab as fallback

October 24, 2026. **Choose FixList: a reusable batch-correction workbench that returns exactly the human’s edited decisions to an agent.** Fallback: HandoffLab restricted to edit–approve–resume contracts for existing agent apps. Neither has validated demand; these are product judgments, not win probabilities. Do not build another broad catalog or evaluation platform.

I independently read the [product](./kane-community-review-product.md), [technical](./kane-community-review-technical.md), [judge](./kane-community-review-judge.md), and [fresh rc.3 research](./kane-community-agent-research.md), plus relevant earlier research. No runtime experiments, agents, installations, external messages, or other file changes were made. Bounded primary-document checks establish advertised overlap, not competitor accuracy or missing capabilities. All proposed flows and adoption claims below remain hypotheses.

**Why the rankings disagree.** Product favored a distributable skill environment; technical favored exportable generated software; judge favored visible recovery behavior. Each assumed its favorite’s hardest part—transfer, host integration, or coordination—would work. Those assumptions are untested. Same-model agreement is not independent market evidence. I prioritize a useful human workflow, an exact browser-dependent oracle, and completion before 6 PM.

1. **Rehearsal: reject as primary.** Portable operational exercises are useful, but [Tessl scenarios](https://docs.tessl.io/improving-your-skills/evaluate-skill-quality-using-scenarios.md), [SkillRank](https://github.com/buildbetter-app/skillrank), and [BrowserGym](https://github.com/ServiceNow/BrowserGym) substantially occupy evaluation, verifiers, bundles, and resettable environments. A synthetic issue board’s pass does not establish transfer to GitHub. Browser necessity is conditional: inspecting a results board adds little; exercising an actual operational UI adds value. Authoring both a world and its oracle is substantial work. Attractive packaging alone cannot establish originality.

2. **SecondTry/HandoffLab: fallback, narrowly.** [LangWatch Scenario](https://github.com/langwatch/scenario) documents multi-turn simulations, custom checks and adapters; [Apple MM-ToolSandbox](https://github.com/apple-aiml-research/ml-mmtoolsandbox) already covers revisions and state mutations. Reject “agents recovering from change” as the originality claim. Accept HandoffLab’s narrower browser boundary: the person’s rendered edit must reach the resumed agent and receiver unchanged. This can serve builders with existing agent apps. Cut SecondTry’s simulated workplace and broad recovery benchmark. Its fatal risk is app-specific hooks and selectors overwhelming reusable contracts; a second ordinary app must reuse the same scenario and evaluator with mappings only.

3. **AppProofStudio: reject today.** It leaves users with useful code, but the [official MCP Apps SDK](https://github.com/modelcontextprotocol/ext-apps) already supplies app-building skills and host/testing machinery, while [MCPJam](https://github.com/MCPJam/inspector) occupies app inspection/evaluation. Exact UI-to-tool payload checks are meaningful browser work. However, verified export, generation, sandboxed-frame automation and bridge correctness are four dependencies before a convincing demo. Kane frame access remains unproven. Even perfect frame access would not distinguish a generator whose main addition is an attached test report.

4. **ToolWitness: reject as standalone.** A receipt is useful when it proves recipient visibility or follow-through; an authoritative API read is usually better for stored fields. MCPJam already makes generic MCP testing a crowded claim. A local board plus a screenshot receipt risks duplicating the application’s own success response. Without a concrete external destination and independent observer requirement, browser necessity and community reuse are too weak. Do not spend today building OAuth integrations to rescue it.

5. **FixList: primary, with modest originality claims.** Agent builders need people to correct structured proposals without reconstructing the batch in chat. The usable flow is proposal → inspect source → edit/exclude records → save/reopen → submit → agent continues with the corrected result. [CopilotKit](https://docs.copilotkit.ai/reference/v2/hooks/useHumanInTheLoop) already supports interactive tools that pause and resume agents with user input. Our proposed difference is a ready-to-use batch editor and portable proposal/result contract, requiring no adoption of an agent framework. That is a packaging hypothesis, not an invented category or proven competitor gap.

**Exact reusable output.** Ship a self-hostable FixList service and small HTTP client. Its versioned JSON contract accepts immutable record IDs, source text, before/proposed values and primitive editable fields; it returns one frozen review revision containing accepted edited records and explicitly excluded IDs. The paused agent receives that result directly; it must not regenerate the human’s decisions from prose. Start with issue-triage proposals and a disclosed local patch export, not claimed GitHub writes.

Kane must sort/filter, edit a named ID, exclude another, reopen the draft and submit. An API-only test cannot establish which record the person saw and edited. A separately authored action fixture defines expected IDs/values; compare Kane’s visible extractions, the receiving agent’s actual tool result, and the applied patch deterministically. Humans judge suggestion quality; this verifies faithful correction and handoff. Probe identity loss after sorting, restored stale drafts, and original proposals leaking into final output—without claiming these failures occurred.

**Second-integration acceptance test.** An independent example agent proposes eval-dataset label corrections through the same HTTP contract. Change only schema, fixtures and the consumer mapping; change no editor, protocol or comparator code. With reordered records and a fresh nonce, Kane edits case B, excludes C and reopens/submits. The dataset consumer must receive and apply exactly the reviewed result. Another triage fixture is not sufficient evidence of reuse.

**One-day cut.** One table/detail editor; primitive fields; draft persistence; explicit submit; one OpenAI-powered proposing/resuming agent; local deterministic consumers; two integrations; one saved variable-based `_test.md`. Preserve reports and commits showing the coding agent reading Kane and changing its next work. Reserve the final build block for clean-clone README, public repo, attached evidence, voiceover and required submission assets. Skip arbitrary schemas, concurrent edits, marketplace and production integrations.

**Three-minute demo.** Open with the bound Kane report and exact received patch. Show a real proposal, human edits and resumed agent; then the second integration using the unchanged editor. Finish with the coding agent’s report-informed commit and replay. If no justified report-driven change exists, that rubric item remains unproven; an invented bug does not fill it.

**Ten-minute falsification spike, proposed only.** Minutes 0–2: freeze three IDs, exact expected edit/exclusion, nonce and independent receiver comparison. Minutes 2–5: create a disposable three-row editor and run one real agent proposal paused at review. Minutes 5–8: Kane sorts, edits B, excludes C and submits; capture visible fields and actual resumed tool result. Minutes 8–10: verify the resulting patch, reset with reordered inputs/new nonce, and attempt strict replay. Stop if browser-to-agent coordination, fresh identity or exact comparison cannot be demonstrated within the timebox. Missing assertions or an uncompleted replay are not green. This tests feasibility, not reliability rates; green throughout is legitimate.

The rc.3 observations support explicit checks, not semantic exploration: exploration missed the price defect/requested second click; explicit checks detected it, while RCA contradicted screenshot evidence. Cached replay passed once and rejected the restored defect once. Keep observed values and deterministic verdicts separate from RCA; those timings are not forecasts. New explore does not improve this product’s core fit.

**Reject FixList even if polished if the second integration requires custom editor code:** then the portable utility collapses into another bespoke approval screen. Reuse the receiver contract for HandoffLab only if an existing agent app passes its mapping-only reuse condition. Otherwise neither candidate is defensible as a portable community product today.
