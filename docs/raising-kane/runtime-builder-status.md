# Raising Kane runtime builder status

The active product path is a generated interface for a supported synthetic website. The user chooses the Northstar return or Linden appointment URL; a blank task yields a read-only overview, from which a supported task can start a separate focused build. Kane Explore maps public navigation in read-only mode. A focused Kane run observes the source and supplies a real screenshot. The OpenAI coding model generates task-specific React and CSS plus a manifest of allowed actions. The app compiles that code into an immutable sandboxed artifact. Kane tests that revision through a trusted source bridge against an independent acceptance contract. A failed interface check can drive at most two code revisions; a passing revision alone is promoted for use.

The current code includes the builder UI, screenshot and map ingestion, bounded inspection tool, generated artifact isolation, separate preview and source Kane queues, synthetic source broker, exact trusted approval, verification reports and source outcome checks. It also preserves URL-based read-only discovery for other websites and the previous fixed sandbox demos.

The scope is the two reviewed local synthetic sources. A supplied unrelated website is rejected for generated transactions; the discovery view remains available for reading arbitrary public sites. Test runs use separate synthetic records and cannot obtain live mutation grants. This is a local process boundary, not an operating-system network sandbox.
